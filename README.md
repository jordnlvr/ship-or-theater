# Saw an AI claim that sounds too good to be true?

Paste in an AI claim you saw online and get a straight answer, with evidence: real (SHIPS), half-true (MIXED) or hype (THEATER).

- Reading a launch post? Find out what actually shipped.
- Vetting a vendor demo? See what the evidence supports.
- Checking a headline before you share it? Get the reasons first.

## Quickstart

Node 20 or newer. Nothing to install.

```bash
# 1. See the rubric. No key, no login, no setup.
npx ship-or-theater rubric

# 2. Score a claim. Uses your Claude Code login, or ANTHROPIC_API_KEY if it is set.
npx ship-or-theater "Our 7B model beats GPT-4 on internal benchmarks." \
  --context "Launch post; no weights or eval suite released."
```

No API key? If [Claude Code](https://claude.com/claude-code) is installed and signed in, every agent call runs through your local `claude` CLI on your subscription. No key, no extra bill.

## Why

AI announcements are easy to make and hard to check. A polished demo, one cherry-picked benchmark or a rebranded wrapper can look exactly like shipped capability. ship-or-theater does the checking the same way every time: it argues both sides, scores six fixed dimensions, and shows its work.

The tool is built to the bar it judges: schema-validated structured output, adversarial verification, graceful degradation and no invented confidence.

## How it works

```mermaid
flowchart LR
    A["Claim + context + URL"] --> B["Extractor<br/>testable assertions"]
    B --> C1["Skeptic: Reproducibility"]
    B --> C2["Skeptic: Evidence quality"]
    B --> C3["Skeptic: Scope honesty"]
    B --> C4["Skeptic: Production-readiness"]
    B --> C5["Skeptic: Novelty"]
    B --> C6["Skeptic: Hidden caveats"]
    B --> D["Steelman<br/>best honest case FOR"]
    C1 & C2 & C3 & C4 & C5 & C6 & D --> E["Judge<br/>score or inconclusive, per dimension"]
    E --> F["Scorecard<br/>verdict · 0-100 · both sides"]
```

1. The **extractor** pulls the discrete, testable assertions out of the claim.
2. Six **skeptics**, one per dimension, run in parallel and hunt for theater.
3. The **steelman** argues the strongest *defensible* case for the claim, without inventing evidence.
4. The **judge** weighs skeptics against the steelman and gives each dimension a score, a confidence and its reasoning, or marks it `inconclusive`.
5. The **scorecard** takes the weighted mean of the usable dimensions and maps it to a verdict.

The skeptic panel runs under `Promise.allSettled`: if one fails, its dimension is `inconclusive` and drops out of the mean. The run never crashes and never fills the gap with a guess.

## The rubric

The rubric is the tool's point of view: fixed, weighted and published. Print it any time with `npx ship-or-theater rubric`.

| # | Dimension | Weight | The question |
|---|-----------|-------:|--------------|
| 1 | Reproducibility | 20% | Could an independent party reproduce it, or is it a cherry-picked demo? |
| 2 | Evidence quality | 20% | Real benchmarks and data, or screenshots and vibes? |
| 3 | Scope honesty | 20% | Does it generalize, or is narrow work dressed up as general? |
| 4 | Production-readiness | 15% | Demo or deployable: latency, cost, reliability, governance? |
| 5 | Novelty | 10% | Genuine new capability, or a wrapper and a rebrand? |
| 6 | Hidden caveats | 15% | What is not said: failure modes, constraints, cost? |

Each dimension scores 0 (pure theater) to 100 (real).

| Verdict | Reality score |
|---------|---------------|
| **SHIPS** | 70 and up |
| **MIXED** | 40 to 69 |
| **THEATER** | under 40 |
| **INCONCLUSIVE** | no usable dimension, so no score |

**Scoring.** Inconclusive dimensions are dropped and the remaining weights are renormalized, so the score stays on a 0-100 scale. If every dimension is inconclusive, the score is `null` and the verdict is `INCONCLUSIVE`. The tool refuses to assert a verdict it cannot support.

## CLI

```bash
npx ship-or-theater "<claim>" [options]
npx ship-or-theater rubric
npx ship-or-theater --version
```

| Flag | What it does |
|------|--------------|
| `-c, --context <text>` | Context around the claim (what was released, what wasn't) |
| `-u, --url <url>` | Source URL for the claim |
| `-f, --format <f>` | `pretty` (terminal view, the default on a TTY), `markdown` or `json` |
| `-j, --json` | Shorthand for `--format json` |
| `--no-color` | Plain output; `NO_COLOR=1` does the same |
| `-o, --out <file>` | Write the scorecard to a file instead of stdout |
| `-m, --model <model>` | Model override. Default `claude-sonnet-5-5`, or set `SOT_MODEL` |
| `--provider <p>` | `auto` (default: the API when `ANTHROPIC_API_KEY` is set, else Claude Code), `api` or `claude-cli` |
| `-V, --version` | Print the version |

```bash
# JSON for a pipeline
npx ship-or-theater "<claim>" --format json --out scorecard.json

# Markdown for a doc or a PR comment
npx ship-or-theater "<claim>" --format markdown > scorecard.md
```

## MCP server

`ship-or-theater-mcp` is a stdio MCP server with two tools:

- **`evaluate_claim`** runs the full pipeline and returns the scorecard (Markdown or JSON, plus structured content).
- **`get_rubric`** returns the rubric and verdict bands. Needs no model.

Add it to Claude Desktop or any MCP client:

```json
{
  "mcpServers": {
    "ship-or-theater": {
      "command": "npx",
      "args": ["-y", "--package", "ship-or-theater", "ship-or-theater-mcp"],
      "env": { "SOT_PROVIDER": "auto" }
    }
  }
}
```

`SOT_PROVIDER` is `auto` (default), `api` or `claude-cli`. With Claude Code installed no key is needed; for `api`, add `"ANTHROPIC_API_KEY": "sk-ant-..."` to `env`.

## Library

The pipeline takes an injected `llm` function, so it embeds anywhere and tests run against a fake with no network.

```ts
import { evaluate, createLLM, renderMarkdown } from "ship-or-theater";

const llm = createLLM({ apiKey: process.env.ANTHROPIC_API_KEY });
const scorecard = await evaluate(llm, {
  claim: "Our 7B model beats GPT-4 on internal benchmarks.",
  context: "Launch post; no eval suite released.",
});

console.log(scorecard.verdict, scorecard.overallScore);
console.log(renderMarkdown(scorecard));
```

## Design principles: honest by construction

- **Inconclusive beats invented.** A dimension with no usable evidence gets no score. Nothing usable at all means no verdict.
- **The LLM layer is isolated.** Only the provider modules talk to a model. Every agent depends on an injected `llm`, so the whole system runs deterministically against a fake in tests.
- **Structured output, validated.** Each agent must return one tool call whose schema comes from zod, then passes `zod.parse`. One retry on a schema failure, then it throws; unvalidated data never moves on.
- **Prompt caching.** The shared rubric and persona block is sent with `cache_control: ephemeral`, so repeated agent calls in a run hit the cache.
- **Graceful degradation.** A failed skeptic makes its dimension inconclusive, not a crash and not a guess.
- **Pure, tested core.** Rubric math and rendering are pure functions with tests that assert computed numbers and band boundaries.

## Roadmap

- Source-URL fetching and citation extraction feeding the extractor.
- Calibration against a labelled corpus of past claims (known ships, known theater).
- Re-run history: re-evaluate a claim as new evidence lands.
- More model providers behind the `llm` interface.
